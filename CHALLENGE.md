# Challenge

This is a working starter app: a gig listing page with a conversational
assistant already embedded (see `README.md` for setup and how the pieces fit
together). The assistant can already hold a conversation, but it knows
nothing about the page it lives on and cannot interact with it — ask it what
gigs are on screen, or ask it to filter the list, and it will tell you
plainly that it can't.

**Your task: make it useful.** At minimum, a user should be able to ask the
assistant questions about the gigs currently on the page, and ask it to take
actions — like filtering or sorting — on its behalf.

There's no skeleton to fill in and no hints about where to hook in. Reading
and understanding the existing code is part of this.

## How we'll work

This is a pairing session, not a take-home — you'll drive, we'll talk
through your thinking as you go. Come ready to narrate your understanding of
the starter app before you start changing anything: what's the data flow,
how does the chat widget talk to the backend, where does the LLM call live.

There are several reasonable ways to bridge the assistant and the page.
Pick one, be able to explain why, and be able to talk about its tradeoffs.

Using an AI coding assistant is expected and welcome — treat it as a
collaborator whose output you're responsible for, not a black box. Be ready
to explain any code in your solution, including anything it wrote for you.

## Getting started

Follow `README.md` to install dependencies and run the app locally. If
you're joining via a shared environment for the session, you won't need to
do this yourself — this is here in case you want to look around beforehand
or the shared session needs a fallback.
